# دیپلوی عمومی روی سیستم شخصی (Windows) — دامنهٔ visionprime-suite.ir

این سند نحوهٔ در دسترس قرار دادن پروژه بهصورت آنلاین از روی همین سیستم را توضیح می‌دهد.
نکته: Docker روی این سیستم نصب نیست، بنابراین نمونهٔ production به‌صورت native
(سرور داخلی PHP) از یک **کپی جداگانهٔ** کد اجرا می‌شود تا استک توسعه (Preview + HMR)
دست‌نخورده بماند.

## معماری

| نمونه | پورت | نقش | از کدام کد |
|---|---|---|---|
| توسعه / Preview | 8000 (+ Vite 5173) | توسعه و پچ‌زدن با HMR | `vision-prime/` (همان workspace) |
| **عمومی / آنلاین** | **80** | سایت قابل اشتراک‌گذاری با دامنه | `vision-prime-deploy/` (کپی همگام) |

> ⚠️ دامنهٔ واقعی `visionprime-suite.ir` است (املای ثبت‌شده sute — نه suite).
> دامنه نزد میزبان فا ثبت شده و NS آن از قبل روی dns1-4.mizbanfadns.net است؛
> مدیریت رکوردها باید در پنل میزبان فا (پیشخوان) انجام شود، نه در صفحهٔ تغییر NS سامانهٔ نیک.

- هر دو نمونه از یک دیتابیس sqlite مشترک استفاده می‌کنند
  (`vision-prime/database/database.sqlite`) → دادهٔ دمو همیشه یکی است.
- نمونهٔ عمومی asset های production (built) را سرو می‌کند؛ نمونهٔ توسعه از Vite.

## وضعیت فعلی (این‌جا خلاصه)

- ✅ `npm run build` انجام شده — خروجی در `public/build/`
- ✅ نمونهٔ عمومی روی `0.0.0.0:80` در حال اجراست (پورت ۸۰ در فایروال بلاک نیست؛ همهٔ پروفایل‌ها OFF)
- ✅ فلو لاگین/داشبورد به‌صورت E2E تست شده (admin@visionprime.test)
- ⏳ DNS و پورت‌فورواردینگ هنوز توسط شما باید ست شود (پایین)

## بروزرسانی سایت پس از هر پچ (دستور sync)

```bash
cd vision-prime
bash scripts/deploy-public.sh
```

این اسکریپت: بیلد assets → کپی به `vision-prime-deploy/` → ری‌استارت سرور پورت ۸۰.

## کارهایی که باید توسط شما انجام شود

### ۱) DNS (در پنل میزبان فا — پیشخوان، نه صفحهٔ NS نیک)
NS دامنه از قبل روی dns1-4.mizbanfadns.net است؛ **صفحهٔ «تنظیمات NS» نیک را دست نزنید.**
وارد پنل میزبان فا (پیشخوان) → مدیریت DNS → دو رکورد از نوع **A** بسازید:

| نام (Name) | نوع | مقدار (Value) |
|---|---|---|
| `@` (خود دامنه: visionprime-suite.ir) | A | `2.147.187.240` ← IP عمومی فعلی (هر بار قبل از ثبت چک کنید) |
| `www` | A | `2.147.187.240` |

> ⚠️ **مهم:** IP عمومی شما پویاست (در همین جلسه از 2.147.195.78 به 2.147.187.240 تغییر کرد). با IP پویا سایت بعد از هر تغییر IP قطع می‌شود؛ راه‌حل‌ها: IP استاتیک از ISP، سرویس Dynamic DNS، یا میزبانی روی VPS.
> ⚠️ اگر پشت CGNAT هستید (IP عمومی مشترک)، پورت‌فوروارد جواب نمی‌دهد و به VPS نیاز دارید.

### ۲) پورت‌فوروارد روتر
در تنظیمات مودم/روتر، یک قانون Port Forwarding بسازید:
- **پورت خارجی:** 80 → **IP داخلی:** `192.168.1.66` (IP محلی این سیستم) → **پورت داخلی:** 80
- پروتکل: TCP

### ۳) تست
بعد از انتشار DNS (معمولاً چند دقیقه تا چند ساعت)، از گوشی (با اینترنت همراه)آدرس `http://visionprime-suite.ir` را باز کنید. اگر باز نشد:
- بررسی DNS: `nslookup visionprime-suite.ir`
- بررسی پورت: سرویس‌های آنلاین «Port Checker» با پورت 80
- Windows Firewall: در صورت بلاک، php.exe و پورت 80 را Allow کنید.

## امنیت (مهم — قبل از اشتراک گسترده)

- اکانت‌های دمو با رمز مشترک **`VisionPrime@Suite-2026!`** عمومی‌اند (از جمله superadmin).
  قبل از انتشار عمومی، رمز همهٔ اکانت‌های دمو را عوض کنید.
- در حال حاضر سایت روی **HTTP** سرو می‌شود. برای HTTPS (توصیهٔ اکید برای production)
  به Nginx/Caddy یا یک VPS نیاز است؛ تنظیمات nginx و Let's Encrypt از قبل در
  `docker/nginx/conf.d/vision-prime.conf` آماده است.
- دیتابیس مشترک بین توسعه و عموم است؛ تغییرات تستی شما روی سایت عمومی هم دیده می‌شود.

## یادداشت فنی: چرا کپی جدا؟

فایل `public/hot` (که توسط `npm run dev` ساخته می‌شود) به Laravel می‌گوید asset ها را از
Vite dev server بخواند. اگر نمونهٔ عمومی از همین کد اجرا می‌شد، به `127.0.0.1:5173` ارجاع
می‌داد که برای بازدیدکنندهٔ خارجی خراب است. کپی دیپلوی بدون `public/hot` این مشکل را
حل می‌کند و asset های built را سرو می‌کند.
