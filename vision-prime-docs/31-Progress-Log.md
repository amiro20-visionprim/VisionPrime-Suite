## ۱) ویژن کلی (خلاصه)

Vision Prime یک پلتفرم self-hosted برای عملیات رشد و هوش SEO است که به آژانس‌های ایرانی کمک می‌کند داده‌های سایت و Google Search Console را به **فرصت‌های رشد قابل‌فهم، توصیه‌های قابل اجرا، تغییرات کنترل‌شده و گزارش قابل ارائه به مشتری** تبدیل کند.

**حلقهٔ ارزش:** `Connect → Collect → Analyze → Prioritize → Recommend → Approve/Automate → Execute → Measure → Report`

**اصول قطعی:** فارسی و RTL first-class هستند؛ هر عملیات حساس audit trail دارد؛ AI فقط copilot کنترل‌شده است (کلید فقط در سمت Laravel)؛ هیچ تغییر پرریسکی بدون Policy مجاز، لاگ و rollback اجرا نمی‌شود؛ پلتفرم Modular Monolith است.

**بازار اول:** آژانس‌های SEO/دیجیتال مارکتینگ ایرانی با چند مشتری و چند سایت WordPress.

سند مرجع کامل: `00-Master-Product-Spec.md`

## ۳) مسیر طی شده تا این لحظه (به تفکیک ستون)

همهٔ موارد زیر **تست Feature سبز** دارند (`tests/Feature/…`) و قابل ردیابی در تاریخچهٔ git هستند.

- **زیرساخت و استک محلی** — استک Laravel 12 / PHP 8.3 / Vue 3 + Inertia / PostgreSQL که روی ویندوز و Docker پروداکشن واقعاً اجرا می‌شود؛ worker صف دائمی + زمان‌بند import روزانه GSC (`e310bdd`).
- **احراز هویت و فانل ورود (J1)** — ثبت‌نام کامل با rate limit، آنبوردینگ و ساخت سازمان، CTAهای رایگان، اصلاح crash داشبورد و اتصال داده‌های واقعی (شمارش سایت‌ها و فرصت‌ها).
- **Workspace** — سازمان‌ها، RBAC (نقش‌ها در `database/seeders/RolePermissionSeeder.php`)، سایت‌ها (CRUD)، داشبورد سازمان، پیشنهادها (Recommendations) با مالک/مهلت/اولویت.
- **کانکتور WordPress** — pairing با توکن، health check امضا شده، دریافت نتیجهٔ دستور؛ رفع مشکلات HTTP واقعی و باندل کردن ریشه‌های CA.
- **GSC** — OAuth با refresh خودکار، انتخاب property با نمایش خطاهای واقعی، import روزانه، metrics، پروکسی HTTP اختیاری برای ایران، موتور تحلیل رشد روی دادهٔ واقعی.
- **هوش SEO** — تحلیل رشد، نقشهٔ intent، URL profiles، صفحات پول‌ساز و ریسک‌های تبدیل.
- **AI و ریویو** — پیکربندی provider، کلاینت، تولید پیش‌نویس متا؛ تغذیهٔ صف بازبینی از خروجی تحلیل رشد؛ تصمیم‌گیری approve/reject با لاگ.
- **اتوماسیون** — تبدیل توصیه به دستور؛ تأیید دستور از لیست و صفحهٔ جزئیات؛ endpoint اجرا (side of plugin آماده است)؛ rollback snapshot.
- **گزارش و پرتال مشتری** — صفحات پرتال: رشد/فرصت‌ها، سلامت سایت، اولویت‌ها، نیازمند تصمیم، فعالیت‌ها، گزارش‌ها؛ انتشار گزارش + رویدادهای impact.
- **مارکتینگ** — لندینگ‌های عمومی (product/features/pricing/demo/security/about/contact)، صفحهٔ قیمت‌گذاری premium، زیرساخت انتساب UTM، فرم دمو واقعی (جدول `leads`)، **نقش Marketing Manager** با داشبورد کامل لید (KPI، فیلتر، جستجو، امتیازدهی خودکار، اعلان لید جدید، یادداشت‌ها) و **قیف تبدیل** (آخرین به‌روزرسانی — بخش ۴).

## ۴) آخرین به‌روزرسانی: قیف تبدیل مارکتینگ (این تغییر)

**وضعیت این تغییر: روی دیسک، کامیت نشده.** شاخهٔ کاری: `new-branch` (۲۵ کامیت جلوتر از origin).

### چه چیزی اضافه شد
- **قیف کلی** (لید → تماس‌گرفته‌شده → واجد شرایط) با نرخ‌های تبدیل؛ وقتی فیلتری فعال باشد به‌صورت خودکار روی دادهٔ **فیلترشده** محاسبه می‌شود (`filteredFunnel`).
- **قیف هر کمپین** (`campaignFunnel`): ۸ کمپین برتر با نوارهای سه‌مرحله‌ای و نرخ‌های تبدیل — مشخص می‌کند کدام کمپین واقعاً مشتری می‌سازد.
- تایپ `ConversionFunnel` در فرانت.

### بهینه‌سازی کوئری (بخشی از همین تغییر)
`funnelForQuery` که قبلاً **سه COUNT جداگانه** اجرا می‌کرد (برای funnel و filteredFunnel مجموعاً ۶ کوئری)، حالا با یک **SELECT تجمیعی واحد** (`count(*)` + دو `sum(case when …)`) محاسبه می‌شود — یعنی به‌جای ۷ کوئری (۶ شمارش + قیف کمپین) فقط ۳ کوئری برای کل بخش قیف.

### فایل‌های تغییر کرده
- `app/Http/Controllers/App/MarketingLeadController.php` — کوئری‌های قیف + متدهای `funnelForQuery` / `funnelItem`
- `resources/js/Pages/App/Marketing/Index.vue` — UI قیف کلی و هر کمپین
- `resources/js/types/marketing.ts` — تایپ `ConversionFunnel` + فیلدهای `funnel` / `filteredFunnel` / `campaignFunnel`
- `tests/Feature/Marketing/MarketingRoleTest.php` — ۲ تست جدید قیف (کمپین + فیلتر)

**نکتهٔ ظریف:** `round()` در PHP برای اعداد صحیح `50.0` برمی‌گرداند ولی JSON اینرتیا نقطهٔ اعشار صفر را حذف می‌کند؛ در تست‌ها باید انتظار `50` (int) نوشته شود نه `50.0`.

## ۱۱) به‌روزرسانی ۲۰۲۶-۰۸-۱۲ — پلاگین v1.1.0 (Rank Math + آیکون) و استقرار روی سایت واقعی liuna.ir (انجام شد)

درخواست کاربر: پشتیبانی کامل Rank Math + رفع نبودِ آیکون پلاگین + بررسی دستی از طریق cPanel.

- **زیرساخت Rank Math در پلاگین:** پلاگین حالا موتور SEO فعال را تشخیص می‌دهد (`RANK_MATH_VERSION`/کلاس Rank Math یا `WPSEO_VERSION`/کلاس Yoast) و دستورهای `update_meta_title` / `update_meta_description` را به کلیدهای همان افزونه می‌نویسد — Rank Math: `rank_math_title`/`rank_math_description`؛ Yoast: `_yoast_wpseo_title`/`_yoast_wpseo_metadesc`؛ اگر هر دو فعال باشند به هر دو؛ fallback به کلیدهای Yoast برای سازگاری. endpoint محتوا هم Rank Math را اولویت می‌خواند.
- **آیکون پلاگین:** ریشهٔ مشکل پیدا و رفع شد — پوشهٔ پلاگین فایل آیکون نداشت (وردپرس برای پلاگین‌های غیر wordpress.org بدون `icon-*.png` آیکون پیش‌فرض خاکستری نشان می‌دهد). اسکریپت `tools/make-icons.php` آیکون برند (گرادیان نیلی→بنفش + VP) را می‌سازد؛ `build.php` آن‌ها را داخل زیپ می‌گذارد (`icon-128x128.png` / `icon-256x256.png`).
- **تست‌ها:** هارنس پلاگین به ۳۰ تست رسید (۲ سناریوی جدید: Rank Math تنها، و Rank Math + Yoast با هم — در فرایند جداگانه با `RANK_MATH_VERSION` تعریف‌شده).
- **بررسی cPanel (سرور 88.135.68.27، حساب `liunair`، دامنهٔ `liuna.ir`):** وردپرس در `public_html`؛ پلاگین v1.0.0 نصب بود و کار می‌کرد (REST health زنده: hash `e102e359…` برابر dist قبلی، `tampered=0` — یعنی سکرت/کانکتور سالم). Rank Math روی سایت فعال است. آیکون‌ها در پوشهٔ پلاگین نبودند → همان ریشهٔ مشکل.
- **استقرار v1.1.0 روی سرور:** فایل 1.0.0 بک‌آپ شد (`dist/_server-1.0.0-backup.php`)؛ فایل جدید با FTP و آیکون‌ها با UAPI آپلود شدند. تأیید زنده: `plugin_version 1.1.0`، `integrity_hash d8ce4aa1…` (بایت‌به‌بایت برابر dist)، `tampered 0`، هر دو آیکون با HTTP 200 + `image/png` سرو می‌شوند.

- **`PolicyEvaluator` (جدید):** تصمیم از بین `auto_publish / pending_approval / rejected / delayed / blocked` بر اساس L0–L4، AI_policy (فقط `bounded_auto` اجازهٔ خودکار می‌دهد)، آستانهٔ اطمینان به‌ازای سطح ریسک (R1=۸۰، R2=۹۰ پیش‌فرض)، max_risk_tier، whitelist نوع دستور/محتوا، سقف روزانه و پنجرهٔ اجرا (شب‌گذر هم محاسبه می‌شود). **fail-closed:** بدون confidence_score هرگز auto_publish نمی‌دهد. **backward-compat:** نبود پروفایل/سیاست = سطح ۱ = مسیر دستی فعلی (هیچ‌چیز رد نمی‌شود). ترتیب منطقی: توقف اضطراری → گیت دستی → whitelist ها (فقط در مسیر خودکار) → R3 → caps → پنجره → آستانه → auto.
- **`AutoPublish` (جدید):** در لحظهٔ پردازش، Policy را دوباره ارزیابی می‌کند (بند Acceptance سند ۰۱)؛ اگر auto_publish → رکورد تأیید با `reviewer_type=system` + `policy_snapshot` (شامل level/ai_policy/آستانه/policy_version) → status=approved + `decision_source=policy` → اجرا از طریق ExecuteCommand موجود → `published_at` ثبت می‌شود. delayed → status=queued؛ rejected/blocked → cancelled؛ pending_approval → بدون تغییر. idempotent (دستورهای پردازش‌شده noop). سقف روزانه در لحظه از دستورهای امروز محاسبه می‌شود.
- **توقف اضطراری:** `EmergencyStop` (فعال‌سازی emergency_stopped_at + cancel دستورهای queued؛ دستورهای در انتظار تأیید انسانی دست نمی‌خورند) + `ResumeAutomation` (رفع توقف). **گارد دوم در `DispatchCommand`:** هر dispatch هنگام ارسال، توقف اضطراری فعلی را دوباره بررسی و مسدود می‌کند (HTTP 423).
- **اتصال به جریان موجود:** `RecommendationController::toCommand` بعد از ساخت command، `AutoPublish` را صدا می‌زند — امروز چون confidence_score وجود ندارد همه fail-closed به تأیید انسانی می‌روند و رفتار قبلی دست‌نخورده است؛ با فعال‌شدن موتور امتیازدهی (فاز ۳) مسیر خودکار فعال می‌شود.
- **تأییدها:** ۱۴ تست واحد PolicyEvaluator + ۱۱ Feature AutoPublish + ۳ Feature EmergencyStop = ۲۸ تست جدید → کل سویییت **۲۰۹ تست / ۱۰۹۴ assert سبز** → pint تمیز روی ۱۰ فایل.
- **قدم بعدی:** 2-4 داشبورد (ویرایشگر پروفایل + سیاست سایت + دکمهٔ توقف اضطراری) و سپس فاز ۳ (حلقهٔ یادگیری از impact_events + بازگشت خودکار R3 + داشبورد «اعتماد به سیستم»).

## ۲۲) به‌روزرسانی ۲۰۲۶-۰۸-۱۴ — فاز ۳ + داشبورد 2-4 + اتصال موتور امتیاز به خط لوله

- **حلقهٔ یادگیری (`LearningLoop`):** job روزانه که از وضعیت واقعی اجراها (executed = موفق، rolled_back = ناموفق) نرخ موفقیت هر (نوع تغییر × سایت) را در ۳۰ روز اخیر می‌سازد و در جدول جدید `automation_learning_history` (migration ۴) upsert می‌کند — پایهٔ `confidence_factors.history`. در `routes/console.php` هر روز ۰۵:۰۰.
- **بازگشت خودکار R3:** سه لایه — (۱) پلاگین: endpoint جدید `/wp-json/vision-prime/v1/rollback` با `restore_command` (متا/تایتل/محتوا) و **snapshot محتوا حالا کامل و بدون‌اتلاف برمی‌گردد** (قبلاً truncate می‌شد)؛ (۲) سرور: `RollbackCommand` snapshot رمزنگاری‌شده را می‌گشاید، درخواست HMAC-امضاشده می‌فرستد، command → `rolled_back`، snapshot → used، outcome در impact_events؛ (۳) `RollbackMonitor` هر ۶ ساعت R3های اجراشده با auto_rollback را با baseline هفت‌روزهٔ قبل از انتشار (از gsc_page_metrics) مقایسه می‌کند و با افت ≥۲۰٪ بازگشت می‌زند. `CommandResultController` هنگام دریافت نتیجهٔ موفق، snapshot پیش‌ازتغییر را خودکار ذخیره می‌کند.
- **داشبورد 2-4 (`/app/sites/{site}/automation`):** `AutomationPolicyController` + صفحهٔ Vue — سطح L0–L4 با label انسانی و راهنما، AI_policy، آستانهٔ R1/R2، max_risk_tier، سقف‌های روزانه، toggle انواع محتوا (meta/article/product)، auto_rollback، انتخاب پروفایل آماده با پیش‌پرکردن مقادیر، دکمهٔ توقف/رفع اضطراری، جدول آخرین اجراها با policy_version. `PolicyEvaluator` حالا overrides_json سایت را روی پروفایل اعمال می‌کند (مدل Default ← Profile ← Override).
- **اتصال موتور امتیاز (`CommandConfidenceAssessor`):** هنگام ساخت command از توصیه، سیگنال‌ها جمع می‌شوند — تازگی همگام GSC (≤۷ روز = ۱٫۰، تا ۳۰ روز محو)، confidence فرصت مبدأ (opportunities.confidence) یا نگاشت اولویت، توافق منابع (rule_based فعلاً)، سابقهٔ یادگیری — و `confidence_score` + `confidence_factors` روی command ثبت می‌شود؛ در نتیجه `AutoPublish` (که از فاز ۲ وصل بود) با سیاست L2+ و اطمینان ≥ آستانه واقعاً خودکار منتشر می‌کند.
- **تأییدها:** ۸ تست جدید (LearningLoop ×2، RollbackCommand/RollbackMonitor ×4، Assessor ×2) → کل سویییت **۲۱۷ تست / ۱۱۱۶ assert سبز** → pint تمیز (۳۴ فایل) → typecheck + lint سبز → route داشبورد 302 به لاگین (auth صحیح، بدون 500).
- **قدم بعدی:** 3-3 داشبورد «اعتماد به سیستم» (نرخ موفقیت انتشار، rollbackها، نمونه‌برداری بازبینی، زمان صرفه‌جویی‌شده) + هشدار R1 و فاز ۴ (چند پروفایل هم‌زمان با مسیریابی ContentType).

## ۲۳) به‌روزرسانی ۲۰۲۶-۰۸-۱۴ — هشدار R1 + داشبورد اعتماد (3-3) + فاز ۴ (چند پروفایل و کپی)

- **هشدار R1 (`RecordMetricDropAlert` + `AutomationAlert`):** `RollbackMonitor` حالا دو مسیر دارد — R1 با افت ≥۲۰٪ فقط هشدار می‌دهد (بدون rollback خودکار) و R3 با پروفایل auto_rollback بازگشت خودکار می‌زند. هشدار = رویداد ممیزی `automation.alert.metric_drop` در connector_events (با **dedupe ۲۴ ساعته** به‌ازای command) + اعلان database به اعضای فعال سازمانِ سایت، فقط اگر `alert_level` پروفایل ≠ none باشد و `notification_policy.enabled` غیرفعال نشده باشد.
- **داشبورد «اعتماد به سیستم» (3-3):** مسیر `/app/sites/{site}/automation/trust` — KPI ها: نرخ موفقیت انتشار خودکار (executed ÷ policy)، تعداد تأیید سیستم (reviewer=system) در برابر تأیید/رد انسانی، rollbackها، زمان صرفه‌جویی‌شده (تخمینی ≈ ۱۵ دقیقه به‌ازای هر خودکار)؛ جدول نرخ موفقیت هر نوع تغییر از حلقهٔ یادگیری؛ نمونهٔ ۱۰ انتشار خودکار اخیر برای بازبینی (نوع، ریسک، اطمینان، وضعیت، صفحه).
- **فاز ۴ — چند پروفایل و کپی:** migration جدول `site_profile_routes` (site × content_type → profile)؛ `PolicyEvaluator`/`AutoPublish` حالا پروفایل را بر اساس ContentType دستور از route انتخاب می‌کنند (مثلاً مقالات L3 آستانهٔ ۹۰٪ کنار متا L2 آستانهٔ ۸۰٪) و `overrides_json` همچنان روی پروفایلِ انتخاب‌شده می‌نشیند؛ UI مسیریابی در داشبورد خودکارسازی (VSelect به‌ازای meta/article/product + ذخیره) و دکمهٔ «کپی» برای ساخت پروفایل سفارشی (`POST /automation/profiles/copy`).
- **تأییدها:** ۶ تست جدید (هشدار R1 ×2 + dedupe، مسیریابی PolicyEvaluator، مسیریابی AutoPublish، کنترلر routes/copy) → کل سویییت **۲۲۳ تست / ۱۱۳۸ assert سبز** → pint تمیز (۴۰ فایل) → typecheck + lint سبز → Preview سالم روی localhost:8000.
- **قدم بعدی (بستن D-013):** Acceptance نهایی فاز ۴ (audit کامل)، داشبورد «اعتماد» قابل‌مشاهده با دادهٔ واقعی بعد از اولین اجراها، و اتصال هشدار R1 به کانال‌های خارجی (ایمیل/تلگرام) از notification_policy.

## ۲۴) به‌روزرسانی ۲۰۲۶-۰۸-۱۴ — اجرایی‌سازی کامل D-013 (بستن شکاف‌ها)

- **حلقهٔ delay → retry (`ProcessQueuedCommands`):** دستورهای منقضی در صف cancel و بقیهٔ queued دوباره از AutoPublish عبور می‌کنند (ارزیابی مجدد Policy در پنجرهٔ مجاز) — هر ۳۰ دقیقه در schedule.
- **کانال‌های خارجی اعلان:** `AutomationAlert` حالا mail (toMail با MailMessage) را هم پشتیبانی می‌کند؛ تلگرام/واتساپ از طریق webhook در `RecordMetricDropAlert` (best-effort و غیرمسدود)؛ `notification_policy` از overrides سایت با پروفایل ادغام می‌شود (override برنده است)؛ UI تنظیم اعلان‌ها (چک‌باکس کانال‌ها + دو فیلد webhook) به داشبورد خودکارسازی اضافه شد + validation بک‌اند.
- **Acceptance یکپارچه (`DAcceptanceTest`):** کل زنجیره در یک آزمون اثبات شد — AutoPublish با تأیید سیستم → سقف روزانه → queued → توقف اضطراری → cancel صف → رفع توقف → انتشار دوباره → بازگشت خودکار R3 با افت زیر baseline (از gsc_page_metrics واقعی) → حلقهٔ یادگیری با total=3/successful=2.
- **اجرایی روی DB واقعی:** `php artisan migrate --force` روی database.sqlite اعمال شد (۵ migration D-013)؛ scheduler (`schedule:work`، PID 37516) و queue worker (`queue:work --sleep=10 --tries=3`، PID 14064) detached در حال اجرا؛ run doc به ۴ پروسه به‌روز شد.
- **تأیید DB واقعی:** جدول‌ها و ستون‌ها موجود (۴ پروفایل seeded)، route های داشبورد 302 به لاگین (بدون 500)، کوئری‌های کنترولر روی DB زنده بدون خطا اجرا می‌شوند.
- **تأیید نهایی:** کل سویییت **۲۲۴ تست / ۱۱۵۱ assert سبز** (Acceptance + ۳ تست جدید) + pint تمیز (۳۴ فایل) + typecheck + lint سبز + Preview سالم.

## ۲۵) به‌روزرسانی ۲۰۲۶-۰۸-۱۵ — تولید مقاله/محصول با استانداردهای محتوا + فاز ۲ انتشار (publish_new_article)

- **استانداردهای محتوا (`ContentStandardsSeeder` + migration `add_auto_publish_scope_and_content_standards`):** جدول `content_standards` با استاندارد مؤثر به‌ازای زیرنوع (meta، مقاله مقایسه‌ای/آموزشی/معرفی، توضیح کوتاه/بلند محصول/مشخصات فنی) — حداقل/حداکثر کلمه، عناصر الزامی (H2، مزایا/معایب، CTA، FAQ)، نسبت تصویر شاخص و اسکیمای پیشنهادی. `StandardsKB` استخراج استاندارد مؤثر را انجام می‌دهد (بدون اعداد هاردکد).
- **تولید پیشنویس (`GenerateArticleDraft` + بازنویسی کامل `RuleBasedDraft`):** هر دو مسیر (AI از طریق `AiClient` و rule-based) خروجی یکسان می‌سازند: متن مقاله/محصول، `featured_image` (ابعاد + متن جایگزین + توضیح تصویر) و `schema` (Schema.org Product/Article/FAQ بر اساس استاندارد — تعیین‌شونده سمت سرور، نه آزاد LLM). ساختار rule-based با عناصر الزامی استاندارد هم‌راستا شد و بخش‌های تکراری «تکمیلی» حذف شد. صفحات Vue مستقل «تولید پیشنویس مقاله» و «تولید پیشنویس محصول» با انتخاب سایت/پروفایل/زیرنوع + نمایش استاندارد مؤثر، گیت‌های کیفیت و نمایش HTML پاک‌سازی‌شده (`ArticleHtmlSanitizer`).
- **فاز ۲ انتشار (`CreateArticlePublishCommand` + هندلر `publish_new_article` در پلاگین):** از پیشنویس تأییدشده کامند R3 `publish_new_article` ساخته می‌شود (idempotent؛ payload شامل title/content/slug/schema)؛ پلاگین وردپرس پست واقعی با wp_insert_post + متای سئو می‌سازد و rollback = حذف پست. گیت‌های `auto_publish` با scope (article=گرمایش ۵، product=گرمایش ۳) + نمره کیفیت محتوا (ContentQualityGuard) + آستانه اطمینان اعمال می‌شوند — انتشار خودکار فقط وقتی گرمایش کامل و کیفیت بالاست.
- **محصول واقعی ووکامرس (`FetchWooProductInfo` + endpoint `/product-info` در پلاگین):** جزئیات بازبینی محصول، قیمت/موجودی/وضعیت واقعی را از ووکامرس (با post_id پس از انتشار یا اسلاگ پیش از آن) نمایش می‌دهد تا بازبین دادهٔ واقعی را ببیند.
- **افزودن `update_content` به جریان UI:** گزینهٔ «تبدیل به تغییر محتوایی» در صفحهٔ پیشنهادها + پشتیبانی در `ConvertRecommendationToCommand` و پلاگین.
- **تأییدها:** ۱۱ فایل تست جدید (۸ Feature: تولید مقاله، صفحهٔ مقاله، خط لولهٔ انتشار، گاردریل‌های AutoPublish، جداسازی پروفایل، حملهٔ replay، جداسازی GSC، گزارش تأثیر + ۳ Unit: RuleBasedArticleDraft، ArticleHtmlSanitizer، ContentQualityGuard) + بازنویسی تست‌های موجود (AutoPublish، Acceptance، RecommendationToCommand، Rollback، GscImport، PolicyEvaluator) → کل سویییت **۲۹۴ تست / ۱۵۹۵ assert سبز** → pint تمیز (۳۲۴ فایل) → typecheck + lint سبز → build تولیدی سالم → E2E واقعی روی WP محلی: مقالهٔ headset-x منتشر شد (`/product/headset-x/`)، بازگشت خودکار و حملهٔ replay تست شد.

## ۲۶) به‌روزرسانی ۲۰۲۶-۰۸-۱۵ — گزارش تأثیر GSC پس از انتشار + ایمپورت متریک‌ها + کارت داشبورد

- **`BuildPublishImpactReport`:** مقایسهٔ دو پنجرهٔ GSC (baseline پیش از انتشار / observed پس از انتشار) برای کامندهای `publish_new_article` — دلتای جایگاه/کلیک/نمایش + وضعیت (بهبود/افت/پایدار) + سری روزانه برای نمودار روند. بدون جعل عدد: اگر صفحه ایندکس نشده یا import نشده باشد `insufficient_data` با دلیل دقیق برمی‌گردد. URL هدف از payload صریح ← کنونیکال اسکیما ← slug + platform_url.
- **کارت «تأثیر محتوا» در داشبورد (`BuildContentImpactSummary`):** همهٔ کامندهای publish اجراشدهٔ سازمان را جمع می‌زند — تعداد گزارش‌شده، توزیع وضعیت‌ها، بهترین/ضعیف‌ترین بهبود و فهرست افت‌ها (مرتب از بیشترین افت کلیک) — فقط بر اساس دادهٔ واقعی GSC. در Preview با دادهٔ دمو تأیید شد: «۱ بهبود، جایگاه -7.28 · کلیک +156».
- **ویجت تأثیر در جزئیات بازبینی:** بعد از انتشار، همانجا گزارش GSC (وضعیت، دلتاهای سه‌گانه، نمودار روند `VTrendChart` با خط انتشار) + لینک مقالهٔ منتشرشده نمایش داده می‌شود؛ ویجت وضعیت کامند (pending/auto_publish/rolled_back + snapshot گیت‌ها + confidence factors) به صفحهٔ «تغییرات اجرایی» هم اضافه شد.
- **`gsc:import` با `--sync`:** ایمپورت روزانهٔ متریک‌های GSC (جایگاه/کلیک/نمایش) به‌صورت همگام بدون نیاز به queue worker + خروجی شفاف و کد خروجی خطا؛ تست Feature آن با متریک‌های روزانه گسترش یافت. گزارش تأثیر حالا با دادهٔ واقعی import شده کار می‌کند.
- **تأییدها:** کل سویییت **۲۹۴ تست / ۱۵۹۵ assert سبز** → pint تمیز (۳۲۴ فایل) → typecheck + lint سبز (۲ باگ lint رفع شد: متغیر بلااستفاده در Dashboard/VTrendChart و هشدار v-html با disable مستند) → build تولیدی سالم → Preview تأیید: کارت داشبورد با دادهٔ واقعی، جزئیات بازبینی با اسکیمای Product + تصویر شاخص + وضعیت انتشار + ویجت تأثیر و نمودار روند، لینک مقالهٔ منتشرشده روی WP محلی HTTP 200.
- **قدم بعدی:** اتصال ایمپورت GSC به scheduler (اجرای روزانهٔ خودکار)، اتصال هشدار R1 به کانال‌های خارجی با دادهٔ واقعی، و Acceptance نهایی D-013 با ممیزی کامل.
