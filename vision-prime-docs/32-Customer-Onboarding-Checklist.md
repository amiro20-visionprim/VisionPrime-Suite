# Vision Prime — چک‌لیست عملیاتی آنبوردینگ مشتری (سایت نمونه: liuna.ir)

> این چک‌لیست مسیر کامل «مشتری» را گام‌به‌گام با هم تیک می‌زنیم: از ثبت‌نام تا اجرای خودکار بهبود محتوا روی سایت واقعی. هر آیتم یک «نتیجهٔ مورد انتظار» دارد؛ فقط وقتی آن نتیجه دیده شد تیک می‌خورد.
> وضعیت: شروع — ۲۰۲۶-۰۸-۱۲. نسخهٔ پلاگین روی سایت: **1.2.0** (آیکون منو + Rank Math + ضد دستکاری).

## فاز ۰ — آماده‌سازی زیرساخت (ما)

- [x] **آدرس پلتفرم مشخص و از بیرون در دسترس باشد** ✅ — پلتفرم پشت **localtunnel با subdomain ثابت** عمومی شد: `https://visionprime-demo.loca.lt` (نمونهٔ عمومی روی `:80` از کپی `vision-prime-deploy` + opcache).
  - نتیجهٔ مورد انتظار: `curl https://visionprime-demo.loca.lt/up` → `{"status":"ok"}` — تأیید شد؛ `/login` و `/register` هم ۲۰۰ (با opcache ~۱.۷ ثانیه).
  - اثبات کامل: pair + health امضاشده (HMAC) از طریق تونل با HTTP 200 پاسخ دادند — یعنی مسیر «اینترنت → تونل → پلتفرم» کار می‌کند و پلاگین بلاک نمی‌شود.
  - پایداری: تونل با **Scheduled Task «VPTunnel»** اجرا می‌شود (بعد از ریاستارت سیستم باید `schtasks /Run /TN VPTunnel` دوباره زده شود).
  - نکته: مرورگر در اولین بازدید interstitial «tunnel reminder» می‌بیند (یک کلیک Continue)؛ درخواست‌های پلاگین (UA وردپرس) بدون interstitial عبور می‌کنند.
- [ ] **پلاگین 1.2.0 روی لیونا نصب و فعال باشد** ✅ (انجام شد — health زنده `plugin_version 1.2.0`، `tampered 0`)
- [ ] **دیتابیس پلتفرم خالی/تمیز برای سناریوی مشتری واقعی** — یا حداقل یک سازمان تست جدا.
- [ ] (اختیاری) **AI Provider تنظیم باشد** — تنظیمات → یکپارچه‌سازی‌ها → AI Provider (برای تولید پیشنویس متا).
- [ ] (اختیاری) **GSC متصل باشد** — برای تحلیل دادهٔ جستجوی واقعی (روی سایت نمونه می‌توانیم بدون GSC هم تحلیل محتوا انجام دهیم).
