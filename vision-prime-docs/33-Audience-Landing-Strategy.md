**تاریخ:** ۲۰۲۶-۰۸-۱۳
**وضعیت:** فعال — مبنای اجرای لندینگ‌های اختصاصی جامعه هدف
**منبع مرجع:** `00-Master-Product-Spec.md`، `31-Progress-Log.md`

> این سند نتیجهٔ تحلیل مشترک با مالک محصول است: پیش از هر طراحی، قدرت اجرایی واقعی محصول، Fit هر جامعهٔ هدف و نرخ تبدیل برآوردی بررسی و **به‌صورت سختگیرانه** نقد شده است. هدف: لندینگ‌هایی که «ویترین» نیستند، بلکه **فانل واقعی** با داده، CTA متناسب و حلقهٔ بازخورد هستند.

## ۱) قدرت اجرایی واقعی (مبنای صادقانهٔ تحلیل)

| داریم (آمادهٔ فروش) | نداریم / ناقص |
|---|---|
| تحلیل رشد، intent، money pages، conversion risks، URL profiles روی دادهٔ واقعی GSC | اجرای خودکار دستور (Command Execution) هنوز تست میدانی کامل نشده — فقط endpoint پلاگین آماده است |
| پلاگین وردپرس v1.2.0 که روی liuna.ir واقعی کار می‌کند (HMAC، rollback، Rank Math) | AI فقط پیشنویس متا است، نه انتشار مستقیم |
| پرتال مشتری + گزارش منتشرشده + قیف لید + امتیازدهی | دسترسی GSC در ایران نیازمند راه‌حل (VPN/پروکسی) — تصمیم باز |
| RBAC کامل، audit trail، گردش‌کار تأیید | استقرار سازمانی (SLA، private deployment) deferred |
| قیمت: پایه ۲.۹M / حرفه‌ای ۶.۹M / آژانس ۱۲.۹M تومان | هنوز مشتری پولی واقعی نداریم (liuna.ir تست میدانی است) |

**Tier 2 — جوامع اضافه‌شده به غیر از کلینیک/آموزش:**
- **سفر و هتلداری** (`/for-hospitality`): هتل‌ها، اقامتگاه‌ها، آژانس‌های تور — جستجوی فصلی «بهترین هتل …»، نیاز به محتوای مقصد، گزارش به مالک/مدیریت.
- **املاک** (`/for-realestate`): مشاوران املاک و پورتال‌های ملکی — جستجوی محلی قوی، ریسک تبدیل محتوا (صفحات منطقه/محله)، گزارش رتبهٔ هر صفحهٔ فهرست.

> این سه بخش با همان معیارها (وردپرس + GSC + قدرت پرداخت) انتخاب شدند و در Tier 2 قرار می‌گیرند، نه Tier 1 — چون ACV پایین‌تر از آژانس و پیچیدگی‌شان بالاست.

## ۴) نقد سختگیرانه (خط‌قرمزها)

1. **هدف همه = هدف هیچ‌کس.** ساخت صفحه برای Tier 3 پیام برند را رقیق و CTA را با واقعیت محصول در تضاد می‌کند.
2. **Tier 3 = فروش محصول ناقص.** بدون GSC/وردپرس چیزی برای تحویل نداریم؛ صفحهٔ فروش برایشان = خرج بی‌نتیجه.
3. **شرکت‌ها وسوسه‌انگیز ولی ناقص.** SLA/private deployment در deferred است؛ بدون پشتوانهٔ اجرایی، ریسک اعتباری.
4. **قیمت پایه برای کلینیک/آموزش سنگین است** اما با «گزارش قابل ارائه به بیمار/هنرجو» و «فرصت‌های محلی» ارزش درک‌شده بالا می‌رود — پیام ساده‌شده لازم است.
5. **قدرت اجرایی ما با Tier 1 جور است** (آژانس/فروشگاه): گزارش، کنترل، شفافیت، چندسایتی — همان چیزی که واقعاً ساخته شده.

## ۷) اقلام معلق — پیش‌نمایش برای بعد

### E-1: اتوماسیون کامل AI (تغییر جهت محصول)
وضعیت فعلی: AI فقط پیشنویس متا + صف بازبینی؛ انتشار دستی. خواستهٔ مالک: اتوماسیون سرتاسری از اتصال تا انتشار، مبتنی بر دادهٔ تصمیم‌ساز. نکته: این D-006 («AI هیچ‌وقت مستقیم publish نمی‌کند») را بازتعریف می‌کند — نیاز به فاز امنیتی/کیفی جداگانه دارد (اجازه‌نامهٔ انتشار، rollback، آستانهٔ اطمینان، audit). **به بعد از بستهٔ لندینگ موکول شد.**

### E-2: GSC در ایران — گزینه‌های پیشنهادی (بر اساس منابع فعلی)
1. **پروکسی API سمت سرور** (Cloudflare Worker یا VPS خارجی): کم‌هزینه‌ترین؛ فقط ترافیک API از سرور خارج می‌رود، کلید OAuth سمت Laravel می‌ماند. زیرساخت `GSC_HTTP_PROXY`/`x-relay-token` همین الان در کد هست (GscRelayTest).
2. **حساب Google متعلق به پلتفرم + refresh خودکار**: برای مشتریانی که دسترسی مستقیم ندارند، ما به‌عنوان نماینده اتصال را مدیریت کنیم (نیاز به توافق/شفافیت).
3. **استقرار پلتفرم روی VPS خارجی**: اگر کل پلتفرم خارج از ایران اجرا شود، مشکل GSC یک‌باره حل می‌شود (اما هزینهٔ زیرساخت و تأخیر ایران).
4. **منبع جایگزین داده** (Bing Webmaster، Ahrefs، ردیابی رتبه): مکمل یا جایگزین موقت برای تحلیل.
5. **ترکیبی (پیشنهادی)**: پروکسی API برای امروز + مستندات راه‌اندازی VPS خارجی برای مشتریان سازمانی. تصمیم نهایی در سند ۳۵.
